# Instrucciones de desarrollo

- Responde en español, de forma directa y práctica.
- Antes de modificar, revisa la estructura y entiende el flujo actual.
- Mantén cambios mínimos, seguros y consistentes con la arquitectura existente.
- No inventes dependencias, rutas ni variables; verifica las existentes.
- No elimines código importante sin justificarlo ni rompas funcionalidades existentes.
- Prioriza validaciones, manejo de errores, logs y seguridad sin sobreingeniería.
- No hardcodees ni publiques secretos; utiliza variables de entorno cuando corresponda.
- Avisa antes de acciones riesgosas y pregunta solo si falta información crítica.
- Explica brevemente el cambio y verifica con pruebas apropiadas.
- Al finalizar, indica qué cambió, por qué, cómo probarlo y qué revisar si falla.
- El README usa el nombre GeekNosy y describe el uso general. Los comandos,
  configuración, API y procedimientos específicos pertenecen a GUIA_TECNICA.md.
- Conserva los identificadores internos heredados DATAGOBS_ y los nombres de
  almacenamiento existentes salvo que se solicite una migración explícita.
